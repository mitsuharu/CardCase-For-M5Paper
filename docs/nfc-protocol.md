# NFC 転送プロトコル v1

M5PaperMono に NFC で画像を送るための決まりです。送る側を自分で実装したい場合はこの文書を参照してください。

実装は以下の 2 か所にあります。どちらも同じ内容で、片方を変えたらもう一方も直す必要があります。

- `lib/NfcTransfer/Protocol` / `lib/NfcTransfer/Session`（本体側・C++）
- `app/src/protocol.ts` / `app/src/nfcSender.ts`（送る側・TypeScript）

## なぜ独自の決まりなのか

NDEF は使いません。NDEF は小さなテキストや URL を置くための形式で、**分割・再開・応答のやり取りができない**ためです。数十 KB の画像を、途中で切れる前提で送るには向きません。

代わりに **NFC-A（ISO 14443-A）の生のフレーム**で独自のコマンドをやり取りします。

## 前提

本体は **NTAG213 として振る舞う PICC（タグ）** です。送る側が PCD（リーダー）になります。

| 項目 | 値 |
| --- | --- |
| RF の層 | NFC-A (ISO 14443-A) |
| タグの種別 | NTAG213 |
| UID | 7 バイト。`0x04` + 本体の MAC アドレス |
| CRC-A | RF の層が自動で付け外しする。**この文書の長さには含めない** |

送る側の API はこうなります。

| 環境 | 使うもの |
| --- | --- |
| iOS | `NFCTagReaderSession` → `NFCMiFareTag` → `sendMiFareCommand` |
| Android | `NfcA` → `transceive` |
| React Native | `react-native-nfc-manager` の `sendMifareCommandIOS` / `transceive` |

## 大きさの制限

| 項目 | 値 | 由来 |
| --- | --- | --- |
| 1 フレーム | **253 バイト** | ISO 14443-A の上限（CRC-A を除く） |
| 見出し | 4 バイト | 印 2 + 版 1 + コマンド 1 |
| DATA の本体 | **241 バイト** | 253 − (4 + 転送番号 4 + 位置 4) |
| 画像 | 262,144 バイト（256 KiB） | 本体のメモリ |

数値は 32bit / 16bit とも**大きい方が先**（ビッグエンディアン）です。

## フレームの形

### 要求

```
+0  0x43 'C'      印
+1  0x43 'C'      印
+2  0x01          版
+3  コマンド
+4  以降           コマンドごとの中身
```

印か版が違うフレームには**応答しません**。他の機器とのやり取りかもしれないためです。

### 応答

```
+0  0x43 'C'
+1  0x43 'C'
+2  0x01
+3  コマンド（要求と同じ）
+4  状態
+5  以降           コマンドごとの中身
```

## コマンド

### HELLO (0x01)

本体の能力を尋ねます。転送を始める前に呼んで、分割の大きさと上限を確かめてください。

要求は見出しだけです。応答の中身は次のとおりです。

```
+5  分割の最大 (2)      DATA で 1 回に送れる本体の上限
+7  画像の最大 (4)      受け取れる画像の大きさ
+11 画面の幅 (2)
+13 画面の高さ (2)
```

```
要求   43 43 01 01
応答   43 43 01 01 00 | 00 F1 | 00 00 10 00 | 01 E0 | 03 20
                状態=OK  241     262144       480     800
```

### BEGIN (0x02)

転送を始めます。

```
+4  全体の大きさ (4)
+8  画像の CRC-32 (4)
```

応答は次のとおりです。

```
+5  転送の番号 (4)      以降の DATA / COMMIT で使う
+9  続きの位置 (4)      ここから送る
```

```
要求   43 43 01 02 | 00 00 00 06 | 86 D3 F8 C2
応答   43 43 01 02 01 | CD 72 34 EC | 00 00 00 00
                状態=受理  番号        続きは 0 から
```

**同じ大きさと CRC で呼び直すと、受け取り済みの位置が返ります。** NFC は数 cm しか届かず切れやすいので、切れたら BEGIN からやり直して続きを送ってください。番号も同じ値が返ります。

### DATA (0x03)

画像の中身を分割して送ります。

```
+4  転送の番号 (4)
+8  位置 (4)
+12 以降  中身（1〜241 バイト）
```

応答の中身は次のとおりです。

```
+5  続きの位置 (4)
```

```
要求   43 43 01 03 | CD 72 34 EC | 00 00 00 00 | FF D8 FF E0 00 10
応答   43 43 01 03 01 | 00 00 00 06
                状態=受理  次は 6 から
```

**位置は必ず続きの位置と一致させてください。** ずれた場合は `BAD_OFFSET` を返し、中身に正しい位置が入ります。そこから送り直してください。

### COMMIT (0x04)

転送を確定します。本体は CRC-32 を検査し、通れば画像を表示します。

```
+4  転送の番号 (4)
```

```
要求   43 43 01 04 | CD 72 34 EC
応答   43 43 01 04 00
                状態=OK
```

検査に失敗した場合は `CRC_MISMATCH` を返し、**受け取り済みの位置が 0 に戻ります**。最初から送り直してください。

### ABORT (0x05)

転送をやめます。

```
+4  転送の番号 (4)
```

## 状態

| 値 | 名前 | 意味 |
| --- | --- | --- |
| 0x00 | OK | 成功 |
| 0x01 | ACCEPTED | 受理した（BEGIN / DATA） |
| 0x10 | BAD_REQUEST | 形式が違う、知らないコマンド |
| 0x11 | BAD_OFFSET | 位置が合わない。中身に正しい位置 |
| 0x12 | TOO_LARGE | 受け取れる大きさを超えている |
| 0x13 | NO_TRANSFER | その転送を知らない |
| 0x14 | CRC_MISMATCH | 中身が壊れている |
| 0x15 | INCOMPLETE | まだ全部届いていない |

誤りの応答の例です。

```
転送が無いのに DATA    43 43 01 03 13
位置がずれた DATA      43 43 01 03 11 | 00 00 00 00   （0 から送り直す）
全部届く前に COMMIT    43 43 01 04 15
```

## CRC-32

IEEE 802.3 の CRC-32 です（多項式 `0xEDB88320`、初期値 `0xFFFFFFFF`、最後に反転）。

**送る側と本体で値が食い違うと転送は必ず失敗します。** 実装したら次の値で確かめてください。

| 入力 | 期待値 |
| --- | --- |
| `"123456789"` | `0xCBF43926` |
| 空 | `0x00000000` |
| `0x00` 1 バイト | `0xD202EF8D` |
| `FF D8 FF E0 00 10` | `0x86D3F8C2` |

## 送る手順

```
HELLO
  ↓ 分割の大きさと上限を得る
BEGIN（大きさ + CRC-32）
  ↓ 転送の番号と続きの位置を得る
DATA（続きの位置から、241 バイトずつ）
  ↓ くり返す
COMMIT
  ↓ 本体が検査して表示する
完了
```

途中で電波が切れたら、繋ぎ直して **BEGIN からやり直します**。同じ大きさと CRC を渡せば続きの位置が返るので、そこから DATA を再開してください。

iOS では `restartPolling`（`react-native-nfc-manager` なら `restartTechnologyRequestIOS()`）を使うと、**シートを閉じずに**繋ぎ直せます。閉じて開き直すと端末が振動して待たされるので、体験がかなり変わります。

## 実装するときの注意

- **速度は約 5.5 KB/秒**です。24 KB で 4〜5 秒かかります。送る前に画像を縮めてください
- **画像は本体の画面（480 × 800）に合わせて縮めます。** それ以上は表示に使えません。回転は本体側が画像の向きを見て行うので、送る側で回さないでください
- **形式は JPEG と PNG のどちらでも構いません。** 本体が中身を見て判断します。文字や図の画像は PNG のほうが小さく、劣化もしません
- **1 フレームごとにログを出さないでください。** 往復が増えて目に見えて遅くなります
